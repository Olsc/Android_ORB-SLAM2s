  问题 1：为什么没有点云时这么卡？

  SLAM 不断丢失跟踪。 该轨迹显示：

  每帧分析：
    ORBextractor       ~21ms  ← 初始化提取器（2 倍特征）减速到 ~10ms
    Relocalization     ~5ms   ← 搜索所有候选关键帧（失败，因为没有地图）
    其他               ~8ms
    总计               ~34ms  ← 用尽 33ms 的帧预算

  该系统每秒运行 11 次重定位+初始化。每次失败，都会在无地图的情况下重试。这完全是正常的 ORB-SLAM2 行为，当你：

  - 快速移动相机（在它建立地图之前）
  - 指向低纹理场景

  对高性能设备的修复：初始 ORB 提取器使用默认的 2*nFeatures。如果我们减少它，初始化帧会更快。在 Config.h 中检查
  ORBextractor::nFeatures 值，或者通过在相机空闲时降低提取率来降低初始化阈值。


问题2：processImage执行过程会卡死

  死锁链：
  1. KeyFrameCulling() 调用 pKF->SetBadFlag() → 持有 mMutexMapUpdate（独占）
  2. TrackLocalMap() 需要 mMutexMapUpdate（共享）来读取地图点 → 阻塞
  3. 这是一个真正的死锁：两个线程都在等待 ORB-SLAM2 的内部映射互斥锁
